# Prompt for the separate GothwadTech profile repository

Copy the prompt below into the coding assistant you use after creating the new
public repository named exactly `GothwadTech/gothwadtech`:

```text
Create a standout GitHub profile README for the GothwadTech account.

Context
- This repository is the special profile repository: its only deliverable is
  README.md. Do not add an app, workflow, package files, or extra assets.
- Gothwad Tech's full official website is https://gothwadtech.com.
- The GitHub Pages showcase is https://gothwadtech.github.io/.
- Developer documentation is https://docs.gothwadtech.com.
- Public repositories are at https://github.com/GothwadTech?tab=repositories.
- A curated starting set includes Accounts, Mail, Drive, Meet, Store, GrixChat,
  GrixChat Android, Gothwad Browser, Gothwad Education, Gothwad AI Studio,
  PlusGit, Gothwad Tube, and Gothwad Docs. Link to each project only when
  useful; don't imply this list is exhaustive.
- Accounts and Mail documentation describe a shared identity project and a
  webmail app with a separate Worker/API. Read their current READMEs before
  asserting technical specifics.
- Gothwad Browser has a public repository, but verify its current license and
  source-availability status before calling it open source.
- The central docs portal explicitly notes where product coverage or production
  verification is incomplete.

Design brief
- Make the first screen memorable and polished: restrained dark/navy palette,
  electric blue accent, strong typography, generous whitespace, clear visual
  hierarchy, concise copy, and a bold hero. Avoid generic corporate jargon,
  emoji clutter, rainbow stacks, giant badge walls, fake dashboards, or unearned
  claims like "India's #1", "fastest", "zero-tracking", or "enterprise-grade".
- Use the hosted banner at
  https://gothwadtech.github.io/profile-banner.svg as the lead visual. Add a
  compact row of high-quality shields.io link badges for the official site,
  docs, and GitHub only. Prefer plain markdown and GitHub-safe HTML.
- Add a short, curated project section with direct source links, a clear
  "Explore all repositories" call to action, and a concise contribution/contact
  section linking to the official website or the relevant repository issues.
- Include a short note that the project list is curated, projects differ in
  maturity, and each repository's README/docs are authoritative.
- Keep it useful on mobile and readable by screen readers. Use descriptive
  link text and alt text.

Accuracy rules
- Do not invent staff biographies, customer names, testimonials, employee
  counts, company registration details, awards, contact email addresses, user
  counts, release status, usage numbers, benchmarks, uptime, performance,
  security, or privacy guarantees.
- A public repo or a product URL is not proof of production availability,
  production readiness, support, open-source licensing, or authorship.
- Do not invent a "tech stack" summary. Link to project READMEs for current
  technologies.
- Only use facts verified from the current repositories and docs. If a claim
  is uncertain, leave it out or qualify it.

Before finishing, inspect the real public READMEs for the selected projects and
review the rendered README preview. Output/change README.md only.
```
